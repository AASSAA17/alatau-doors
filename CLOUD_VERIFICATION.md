# Проверка подготовки Vercel + Neon

Первичная подготовка: 28 октября 2026. Среда: Windows, Node.js 24.22.1, npm, Next.js 16.4.3; отдельный PostgreSQL 18 на loopback:55432. Установленный сервис PostgreSQL на 5432 не использовался. Облачное развёртывание выполнено отдельно 29 октября с разрешения владельца.

## Открытая регистрация BUYER — 29 октября 2026

По запросу владельца код приглашения удалён из формы, HTTP-проверки, обязательной конфигурации и RU/KK подсказок. Новая регистрация принимает только имя, email и пароль от 12 символов. Секрет Better Auth, аккаунты, сессии, данные и дизайн не менялись. Остальные ограничения публичной демонстрации сохранены.

Перед публикацией обновления проверены:

- TypeScript/typegen и ESLint — успешно.
- Production build с PostgreSQL и ограниченной SQL-ролью — успешно. Проверка выполнялась в отдельной копии исходников; работающий `.next` презентации не перезаписывался.
- **7/7 HTTPS Playwright тестов прошли за 17.7 секунды**: регистрация без приглашения с шириной 390 px, отсутствие поля на RU/KK, роль BUYER, cookies/сессия/избранное; весь процесс заявки и ограничения ADMIN; DTO/Origin/лимиты/история.
- Новый тест подтверждает ровно 10 допустимых регистраций за окно 24 часа, затем `429 DEMO_LIMIT`. Неверный Origin и поддельная роль не расходуют квоту регистрации. Лимит 50 аккаунтов по-прежнему выдерживает конкурентные INSERT.
- SQL permissions и запреты небезопасного окружения прошли. Обе исходные SQLite-базы сохранили все 11 контрольных сумм; порт 3200 отвечает 200.

Повторная установка зависимостей в тестовую копию на Windows остановилась из-за отсутствующего C++ toolchain. Для проверки использованы уже установленные зависимости проекта той же версии; исходный `node_modules` не изменялся. Предупреждение Next.js о двух lockfile связано с расположением временной копии внутри `.local`, в Vercel этой копии нет.

Ниже сохранены результаты первоначальной публикации; упоминания приглашений в них описывают предыдущую версию.

## Отдельный публичный режим

HTTPS-тесты обращались к `https://127.0.0.1:3343`, локальный TLS terminator проксировал production Next.js на 3300. Self-signed сертификат разрешён **только тестовым браузерным контекстам**; проверка TLS удалённой БД в приложении не ослаблялась.

Проверено:

1. Регистрация BUYER через казахскую форму с приглашением; отказ без приглашения, с чужим Origin и с попыткой задать ADMIN. Cookies имеют Secure, HttpOnly, SameSite=Lax и secure prefix. Новая браузерная сессия восстанавливает избранное. Новый покупатель может менять свой пароль, включая вымышленный адрес в домене alatau.demo.
2. Полный процесс создания, назначения, расчёта, просмотра покупателем и завершения заявки. Две одновременные публикации одной revision дают 200 и 409; сохраняется ровно одна версия расчёта. Закрытая заявка не редактируется.
3. Публичный ADMIN не может создавать сотрудников, повышать BUYER, отключать SELLER или менять пароль общего seed-аккаунта. Неиспользуемые auth endpoints недоступны; форма управления учитывает ограничения.
4. Поддельные суммы, несуществующие варианты, неверный Origin и слишком большие тела запросов отклоняются. Не создаётся частичная заявка после отказа.
5. Допустимая сумма **6 000 000 000 ₸** проходит BIGINT round-trip как JS number; изменение/архивация товара не меняет сохранённый расчёт.
6. Лимит записи блокирует burst запросов одного аккаунта кодом 429, не блокируя другой аккаунт.

Дополнительные assertions выполняются вне браузера:

- Runtime SQL-роль не может создавать таблицы, изменять app_meta, удалять quotes или переписывать request_events.
- Публичный режим принимает корректный marker + ограниченную роль; отвергает owner credentials, отсутствие marker, HTTP auth-origin, SQLite на Vercel и попытку переключить публичную seeded-базу в production/local-demo.
- Отдельный SQLite fixture с production-именем, но seed-маркером, отклоняется: переименование локальной демобазы не снимает защиту.
- Два конкурентных INSERT при 49 пользователях приводят ровно к одному успеху и одному SQL `23514`; итог — ровно **50 аккаунтов**. Проверен именно DB trigger, независимо от HTTP rate limit.

## Сохранность локальных данных

Контрольные суммы до/после совпали для `products`, `variants`, `user`, `requests`, `request_items`, `quotes`, `request_events`, `internal_comments`, `store_settings`, `drafts`, `favorites` в обеих исходных базах: `.local/alatau-demo.sqlite` и `.local/presentation-demo.sqlite`. Тесты создавали отдельные базы и случайные доступы; исходные пользовательские таблицы не наполнялись заново и не сбрасывались. SQLite WAL может изменять технические файлы без изменения бизнес-данных.

После проверок отдельный тестовый PostgreSQL на 55432 остановлен, его данные сохранены в `.local/postgres-test`. Для следующего прогона сначала выполните `npm.cmd run test:postgres:setup`. Сервис 5432 продолжает работать. Презентационный сервер на 3200 оставлен запущенным.

## Что ещё зависит от владельца

Не проверялись живой Neon pooler, настройки реального Vercel-проекта, публичный DNS/TLS и исполнение GitHub Actions: эти внешние ресурсы не созданы по условию задания. Подготовленный workflow не равнозначен его успешному запуску в GitHub. Финальный smoke-test на реальном домене, включая redeploy и сохранность сессий/данных, описан в `VERCEL_DEPLOYMENT.md`.

Это подтверждение локальной работоспособности и готовности конфигурации, а не утверждение о состоявшемся публичном развёртывании или о готовности к коммерческой эксплуатации с реальными персональными данными.
