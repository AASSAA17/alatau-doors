# Резервные копии и проверка восстановления

Команды запускает оператор в приватном терминале. В кабинете сайта нет скачивания базы.
Платные сервисы и расписание не подключаются автоматически. Инструмент рассчитан на небольшой
каталог: архив до 256 МБ, фотографии в приложении ограничены суммарно 100 МБ / 500 файлами.
При росте требуется отдельное объектное хранилище и потоковая система копирования.

## Создание

Нужны Node 24 и PostgreSQL client 18 (или совместимый с версией сервера). На Windows по умолчанию
используется `C:/Program Files/PostgreSQL/18/bin`; переопределение — `POSTGRES_BIN`.

```powershell
# PostgreSQL: env-файл содержит direct owner URL, не runtime URL
node --env-file=.env.cloud.local scripts/backup.mjs postgres
# SQLite: явный путь к существующей базе; online backup учитывает WAL
npm run backup -- sqlite .local/presentation-demo.sqlite
```

Путь SQLite выше — пример: сначала сверить DATABASE_PATH презентации. Скрипт не создаёт отсутствующую
исходную БД. PostgreSQL копируется pg_dump в согласованном snapshot; исходные строки не меняются.
Пароль передаётся дочернему процессу через окружение, а не аргументы командной строки.
TLS Neon проверяется по доверенным корневым сертификатам, поставляемым с Node.js; отключать проверку нельзя.

Результат — новый `.local/backups/*.adbackup`, AES-256-GCM с отдельным случайным nonce.
Ключ автоматически создаётся один раз в `.local/backups/backup-key.bin`; существующий не заменяется.
Можно заранее задать `BACKUP_KEY_FILE` на приватный файл из 32 случайных байт.
Скопировать ключ в менеджер секретов/защищённый отдельный носитель. Архив без ключа невосстановим.
Для восстановления авторизации отдельно сохранить BETTER_AUTH_SECRET, параметры Google и почты:
смена секрета Better Auth может сделать зашифрованные MFA и OAuth-данные нечитаемыми.

Архив содержит персональные данные, хеши паролей и сессии. Не отправлять его в чат, почту, Git или
общедоступное облако. На Windows каталог должен быть доступен только владельцу и системным
администраторам; Unix mode 0600 не заменяет Windows ACL. Не хранить единственную копию на одном ПК.

## Проверка восстановления

```powershell
npm run test:postgres:setup
npm run backup -- verify .local/backups/<имя-архива>.adbackup
```

Сначала полностью проверяется подлинность архива. Для PostgreSQL создаётся новая случайно названная
БД только на loopback-сервере из PG_TEST_ADMIN_URL или `.local/postgres-test/config.json`.
pg_restore выполняется одной транзакцией с `--clean --if-exists` **только в этой новой временной БД**.
После проверки количества строк временная БД удаляется. В исходную базу команда не пишет.
SQLite восстанавливается в новый временный файл, проходит integrity_check и foreign_key_check;
временный файл после проверки удаляется. Числа строк выводятся без содержимого записей.

Автотест `npm run test:backups` проверяет SQLite с WAL, PostgreSQL, отказ при изменении шифротекста,
отказ восстановления на удалённый сервер и сохранность источника. Это не заменяет сравнение
бизнес-данных после аварийного восстановления и ручную проверку входа/заявок.

## Реальная авария

1. Остановить запись в повреждённое окружение, сохранить его для расследования. Не запускать seed.
2. Найти последнюю проверенную копию, ключ и прежний BETTER_AUTH_SECRET.
3. Проверить архив командой verify. Восстанавливать рабочее окружение только в **новую пустую БД**
   через приватный операторский доступ; текущий скрипт намеренно не выполняет удалённый restore.
4. Применить runtime-права и недостающие добавочные миграции; проверить товарные фотографии,
   заявки, версии расчётов, роли, MFA, почту. При инциденте доступа отозвать восстановленные сессии.
5. Переключить подключение приложения на проверенную БД. Старую не удалять до приёмки владельцем.

До коммерческого запуска согласовать расписание (например ежедневно и перед изменениями), срок
хранения, ответственное лицо, внешнее зашифрованное хранение и допустимые потери данных/простой.
Сейчас автоматическое внешнее копирование и мониторинг его выполнения **не настроены**.

Основа: [pg_dump 18](https://www.postgresql.org/docs/18/app-pgdump.html),
[pg_restore 18](https://www.postgresql.org/docs/18/app-pgrestore.html).
